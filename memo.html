The Reasoning Problem

Membrane Labs · September 2026

Agents write more of the work every month. Code first, and soon most of the routine work a company runs on. But every agent starts from nothing. It reasons through a task, reaches a result, and then the session closes and the reasoning is gone. The output survives. The thinking that produced it does not.

That is the waste we are building against.

An agent's real work is not the code it writes. It is the reasoning it does to get there: the approaches it weighed, the ones it rejected and why, the constraints it was holding when it chose one path over another. The output is all of that compressed into a single answer. Read the answer later and you see only the answer, never the reasoning behind it. For anyone who has to trust that answer, the reasoning was the part that mattered.

Alone, this is survivable. The reasoning still lives in the head of the one person who ran the session. On a team it does not. One engineer's agent works out how a service actually behaves, and no one else's agent can reach that. A session figures out why an approach fails, and the next session starts cold and figures it out again. Multiply this across a team and most of what the agents learn gets learned repeatedly, because nothing any of them figures out lives past the session it happened in. Teams running agents seriously already lose hours per engineer every week to exactly this, rebuilding context that had already been built and thrown away.

The reflex is to patch this one session at a time: better summaries, better commit messages, better pull request descriptions. That treats the symptom. The session is the wrong place to keep anything, because the session is built to expire. The fix is a memory that sits underneath every session, that each agent reads from before it starts and writes to as it works, so reasoning accumulates in one place instead of dying in a thousand. That shared memory is the thing we are building.

You cannot build shared memory in the abstract. You need a real source of reasoning to capture, and a place where its absence hurts enough that capturing it is worth something on the first day. Code review is both.

When an agent writes code, the diff shows exactly what changed and nothing about why. The reviewer has to decide whether to trust agent-written code with no access to the reasoning that produced it. The dangerous case is not the code that fails a test. That announces itself. It is the code that passes everything and is still wrong, because the agent answered a slightly narrower question than the codebase actually needed, and no one could see the assumption it made along the way. Green stops meaning what reviewers think it means.

So we start there. Before a pull request opens, we read the agent's session and surface what it decided, what it rejected, and what it was assuming, at the lines where those choices became code. The reviewer stops guessing at the reasoning and starts checking it.

This is not a detour from the memory layer. It is the first pipeline into it. Every decision we surface for a reviewer is a decision written to the shared store. The review product and the memory are one system, entered at the point where the loss is sharpest and the value is easiest to see. Solve review well and the memory fills as a byproduct of work people already do.

Code is where we start, not where this ends. The reasoning agents discard is not specific to code. A team of agents handling procurement, or support, or operations loses the same thing at the same boundaries: the why behind a decision, gone the moment the session that made it closes. The memory we build for coding agents is the substrate those agents need too. We start with code because it is the sharpest instance of the problem, and the one where the reasoning is most capturable today, not because it is the ceiling.

The durable thing a team owns is not the model. Everyone has the same models. It is the accumulated reasoning of everything its agents have worked out: the decisions, the dead ends, the constraints learned the hard way.

Right now that is discarded every session. We are building the place it lives.
